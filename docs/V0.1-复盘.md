> 更新时间：2026-09-07

## 一、V0.1 做了什么

### 核心流程
语音录入 → 浏览器实时转文字（Web Speech API）→ AI 结构化整理（Anthropic API）→ 用户 Review/编辑 → Confirm & Save → 历史存档 / 个人统计。

### 前端
- 单文件 SPA（`public/index.html`），Tailwind + Iconify，藕粉色系视觉风格
- 页面：登录/注册、首页（真实统计 + 训练小提示轮换）、录音（引导卡片 + 手动补充输入）、AI 处理中、复盘草稿编辑、历史存档（关键词搜索）、记录详情、我的（真实统计 + 关于弹窗）
- 语音识别兼容性处理：不支持的浏览器（Firefox）自动降级为手动输入；iOS Safari 等运行时报错（`service-not-allowed`）也会优雅降级，不会卡死用户
- 移动端交互打磨：44px 最小触摸目标、点击反馈、去除点击高亮闪烁、键盘焦点样式

### 后端
- Express + better-sqlite3，标准分层结构：`app.js`（组装）/ `config.js`（环境变量）/ `db.js`（数据库）/ `middleware/auth.js` / `routes/*.js`
- JWT 登录鉴权，`users` 表 + 每条 `records` 按 `user_id` 隔离，用户之间数据互不可见（有测试验证）
- AI 接口用 Anthropic **tool-use** 强制结构化输出，避免了"模型在字符串里加引号导致 JSON 解析失败"这类真实 bug
- 埋点：`events` 表 + 9 个事件（`record_voice_start/complete`、`asr_fail`、`ai_process_success/fail`、`retry_ai`、`save_record`、`user_edit_ai_result`、`history_open`），独立的 `/stats.html` 内部看板（需要 `ADMIN_KEY`，不对普通用户开放）

### AI Prompt
- 已对照《Prompt Design Document V1.1》逐句核对，补全了当时遗漏的"禁止抒情评价语言"和"不替代专业教师"两条规则
- Output Schema 改成文档要求的数组格式（服务器端再拼接成前端需要的换行字符串，前后端都不用改）
- 接入了文档里的 few-shot 示例，实测输出和文档期望值基本一致
- 补充了 Rule 4 的具体反例，实测能正确拒绝"用户没说过的训练建议"这类幻觉

### 测试与部署
- 17 个后端单元测试（`node --test`），覆盖鉴权、数据隔离、AI 接口、埋点、管理统计接口
- 部署在 Render 免费版，GitHub 推送后自动部署；踩过的坑：Render 默认 Node 版本太新导致 `better-sqlite3` 编译失败，已用 `.node-version` 固定为 18.x

## 二、PRD vs 实际实现 差异对照

| PRD 里怎么写的 | 实际做了什么 | 状态 |
|---|---|---|
| 第3节把"轻量 Progress"列为 **Must Have**，第4.6节要求跨历史记录发现重复训练问题（例："Pirouette重心稳定性，最近4次记录中出现3次"） | **未实现** | 🔴 唯一一个"文档要求必须做、但没做"的功能，已决定推迟到 V0.2 |
| Output Schema 定义 `good_points`/`improve_points`/`next_time_reminder` 为数组 | AI 请求层已对齐为数组；存库和前端展示层仍是**换行分隔的字符串**（可编辑文本框比动态列表 UI 简单很多） | 🟡 有意的简化，已确认 |
| PRD 第7节定义10个埋点事件 | 已实现9个，`progress_open` 因为对应功能未做暂缓 | 🟢 基本完成 |
| History 明确写"MVP 不支持多维搜索和筛选" | **做了搜索框**（按课程名/内容关键词） | 🟢 超出文档范围，属于合理加量，文档需要同步更新 |
| Out-of-Scope 写"没有复杂账号和会员体系" | 做了完整的邮箱注册 + JWT 登录（为了多用户数据隔离，是后来在讨论中明确要求加的） | 🟡 合理的产品升级，超出原始文档范围 |

## 三、设计原型稿 vs 实际实现 差异对照

（原型来自 modao.cc 导出的 7 个页面：home / voice / processing / review / detail / history / profile）

| 原型页面 | 原型里有、实现里没有的 | 原因 |
|---|---|---|
| 全部页面 | 完全没有登录/注册页 | 原型工具通常不建模鉴权流程，属正常现象 |
| detail.html | 音频波形 + 播放按钮、AI 按时间戳分段的时间轴、训练标签(#tendu)、书签按钮 | 明确决定不做：不保存原始音频、不做标签系统 |
| processing.html | 假的百分比进度条动画 + 三步骤清单 | 我们是真实等待 AI 接口返回，没有编造进度 |
| review.html（原型） | 一句话"AI训练摘要" + 分享按钮 | 保留了 PRD 要求的三段式可编辑文本框结构，没做摘要和分享 |
| home.html（最新版原型） | 顶部统计卡片被拿掉了；最近记录卡片显示假的"AI识别5条/完成度良好"统计 | 我们保留了真实统计卡片，最近记录卡片不展示编造的数据 |
| profile.html | 假数据（"已练习12周"/28次/16.4小时/连续7天）、训练目标与隐私设置项、编辑头像按钮 | 我们坚持只展示真实数据（次数/时长/本月次数/加入天数），暂不做那些设置项 |

**结论**：原型的价值（配色方向、移动端交互细节：点击反馈、44px触摸目标、去高亮闪烁）已经吸收进实现里；功能性的差异都是主动的、可以解释的裁剪，不需要回头修改原型去"追平"。

## 四、下一步建议（按优先级）

1. **持久化存储（🔴 优先级最高）**：Render 免费版磁盘不持久化，每次重新部署 SQLite 数据都会清空。对朋友测试问题不大，但真实用户变多或者演示时不小心 push 一次代码就可能丢数据。建议：Render 付费持久磁盘（约 $1/GB/月）或迁移到 Supabase 免费云数据库。
2. **Progress 功能**：PRD 里唯一的 Must Have 缺口，跨记录发现重复训练问题。建议作为 V0.2 的核心功能。
3. **忘记密码流程**：目前没有密码重置，对朋友测试影响不大，但如果面试官等外部人自己试用，忘了密码会卡住。
4. **可选**：更新 PRD 文档，修正 "BarreNote" 笔误，同步 History 搜索、登录系统等已经超出原文档范围的实现。
