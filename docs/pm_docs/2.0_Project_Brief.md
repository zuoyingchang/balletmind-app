## 项目背景

芭蕾课结束后，练习者习惯口头复盘：哪里做得好、哪里不稳、老师指出什么。多数人只在脑子里过一遍，或随口说说，不会沉淀成结构化笔记；课后打字又太重。通用聊天机器人容易编造「你没说过的训练建议」。

BalletMind 让用户用语音口述这次课，先转写、再由 AI **忠实抽取**成结构化草稿，人确认后才进档案。界面两段：**做得好的** / **还要改的**（口述里的「下次」写进还要改的，不再单独一栏）。跨多次课后，用规则把反复出现的待改进点聚在一起；课前看最近一则仍带「还要改的」的课记；按 7 天或最近 5 次能汇总。追踪里还可 **查查我的档案**：RAG 先按关键词找自己确认过的课记，命中太少（0 或 1 条）再用 Embedding，然后**按原文列出**做得好的 / 待改进（问档案时才加已解决）。不让大模型另写一段「综合回答」，也不替用户宣布进步。

## 目标用户

**核心用户**：持续上成人芭蕾课、希望把老师反馈和个人感受记下来的业余–进阶级学习者。

**当前验证阶段**：作品集 + 身边非正式试用。正式 **3–6 人结构化访谈尚未做**。家长端、老师端仍是假设画像，不是本版交付对象。

**用户痛点（仍成立）**

1. 课后只想随口说，不想打长笔记  
2. 口述零散，没有「优点 / 待改进 / 下次注意」  
3. 内容会忘，缺少可回看的档案  
4. （2.0 补上）记了很多次仍看不见「哪条问题反复出现」、上课前没有一张短卡

## 一句话定位

课后 1–2 段语音口述 → Whisper 转写 → LLM 结构化草稿 → 人确认后存档；跨课次用规则追踪反复问题、给课前短提醒；需要时用检索列出自己的课记原文。**AI 整理原话或并列引用已保存内容，不诊断动作，不替用户宣布进步。**

## In-Scope（当前产品真实范围）

1. 录 1–2 段语音，各约 1 分钟；不支持语音或额度用尽时可**手动记**（打卡式一页，两段事实必填）  
2. 服务端 Whisper ASR（带芭蕾术语提示）；可选腾讯云转写备用（默认关）；浏览器不支持时降级手打 / 手动记  
3. AI 抽取：做得好 / 待改进（含口述「下次」）+ 空的 `next_time_reminder` + 可选 `session_tips` + 置信度 + note；tool-use 强制 schema；界面只露出两段事实  
4. Review / Edit / Retry / 确认保存；未确认不入库；课程/组合用芯片（基训 / 把杆 / 拉伸软开 / PBT / 跳跃组合等，最多约 10 个）  
5. 历史档案：统计（含时长趋势周/月）与列表；查看、删除、关键词搜索（中英法术语对照可搜）  
6. Progress：反复问题（出现 ≥1 次即列出，按次数降序；文本匹配 + 用户改状态）、证据回链课次、课前看一眼（最近一则仍有「还要改的」的课记，**默认 0 次 LLM**）、近 7 天 / 近 5 次规则汇总。多 Agent 课前卡是 Experiment，双开关默认关。  
7. **查查我的档案**：追踪「回看」里提问。RAG 先关键词；命中 0 或 1 条时再 Embedding。服务端按行列出原文（每栏先 5 条，可再加载），引用可点回课次。没有相关记录就如实说没有。仓库里的 `ASK_PROMPT` 不作现网路径。  
8. 轻量账号：邮箱注册、JWT、隐私同意、找回密码；未填昵称时用邮箱 @ 前一段作显示名；「我的」可导出全部数据或注销删账号（需密码确认）  
9. 配额：**每天免费 AI 复盘 2 次**；**每周问档案 10 次**（周一本地 0 点重置）。转写另有防滥用日封顶。Turso 持久化、内部 `/stats.html`、离线 Eval（约 35 条测抽取 Prompt 2.2；问问档案有检索/digest 对照，不测二次写作）  
10. **界面**：底栏四项（首页 / 记录 / 档案 / 追踪），「我的」从头像进；确认页两段必填 + 课程芯片；生成与保存吸底；首页日历默认一周、可展开整月；今天已写过完整复盘则主按钮为「再记一节」；可选心情为用户自报，AI 不推断  
11. **只打卡**：至少一条完整复盘之后可先打卡；打卡必选课程/组合；与课记同一张表、同一套日历；不占 AI 复盘额度、不算语音漏斗完成。可保存打卡图自己发。

## Out-of-Scope（明确不做）

1. 视频动作识别、AI 打分、伤病/医疗诊断  
2. 社交、社区、应用内动态流（打卡图可保存后自己发，不是站内社交）  
3. 实时语音对话  
4. Fine-tuning、用模型写周报/月报、芭蕾百科问答、教练式对话  
5. 老师端、家长端、课程交易、会员分级  
6. 老师寄语对照、反复问题图表、课后主动 Push（方案另存，未做）  
7. 勾选式「未完成清单」、聚合场景专用 LLM Prompt  
8. 「心情色打卡」体系（连续打卡色、情绪评分）；现网仅有可选自报心情，与此不同

## 成功衡量（三层，不编目标数字）

**北极星（产品层）**  
同一 `sessionId` 的语音漏斗走到确认保存的比例：开始录音 → 录完 → ASR 成功 → AI 成功 → 打开 Review → 确认保存。  
禁止用「开过录音的独立账号 ÷ 保存过的独立账号」。

**Layer 1 AI 质量（离线 Eval）**  
Field Coverage、Classification、Hallucination-free / Unsupported Content、Terminology、Schema Validity。命令：`cd server && npm run eval`。

**Layer 2 系统**  
ASR/AI HTTP 成功率、P95 延迟、DeepSeek / Anthropic token 与估算费用、Whisper 次数与按分钟估算费用、失败原因、Retry。看板：`/stats.html`。原始埋点：同页底部按事件名查询（无转写/邮箱）。

**Layer 3 产品**  
Activation、Completion（session）、Edit Rate（≠ AI 错误率）、Regenerate、History Revisit、D7（样本极小时不当结论）。

次要指标 1.0 里把 Edit Rate 当成「AI 错了多少」——**2.0 纠正**：改口吻也算编辑。

## 核心风险与现网对策

| 风险 | 2.0 对策 |
| --- | --- |
| ASR 术语错 | Whisper + 术语 prompt；模型侧词汇表只用于「听懂」，对不上就降置信度；用户纠错过的术语写入后续 prompt |
| 口述太少 | 不补全优点/待改进；保存前两段事实必填（空则提示必选） |
| 幻觉（编问题/建议） | Prompt 护栏 + tool schema + 人审；黄金集含 hallucination / injection / safety |
| 跨记录「你进步了」幻觉 | 反复问题 / 课前卡 / 窗口汇总 **默认不用 LLM**；问问档案只并列引用，Prompt 禁止进步/退步措辞 |
| 超时/失败 | 保留转写；Retry / 手动记；AI 复盘每天 2 次，问档案每周 10 次；主路径超时约 25s（备用可约 5s 接手）/ ASR 约 30s |
| 成本 | 抽取默认可配 Anthropic Sonnet 5 或 DeepSeek；问档案现网不另耗写作 token |
| 数据丢失 | 训练记录在 Turso，redeploy 不清空；本机每周 JSON dump 到私人目录 |

## 当前状态（实话）

- 主流程、规则版 Progress、查查我的档案（检索+原文）已上线。  
- 多 Agent 课前提醒已接线、默认关闭，未对任何用户开启，不算 2.0 已做。  
- 非正式亲友反馈：流程能跑通、界面清楚；结构化 3–6 人测试未做。  
- Layer 3 规范漏斗依赖带 `sessionId` 的部署；旧事件不回填。  
- 生产若仍钉死 `AI_MODEL=claude-sonnet-4-6`，代码默认的 Sonnet 5 不会生效。
