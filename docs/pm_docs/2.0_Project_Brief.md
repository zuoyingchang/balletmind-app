## 项目背景

芭蕾课结束后，练习者习惯口头复盘：哪里做得好、哪里不稳、老师指出什么。多数人只在脑子里过一遍，或随口说说，不会沉淀成结构化笔记；课后打字又太重。通用聊天机器人容易编造「你没说过的训练建议」。

BalletMind 让用户用语音口述这次课，先转写、再由 AI **忠实抽取**成结构化草稿，人确认后才进档案。跨多次课后，用规则把反复出现的待改进点聚在一起，课前能看一眼，按 7 天或最近 5 次能汇总。追踪页还可 **问问你的档案**：RAG 先按关键词找自己确认过的课记，命中太少（0 或 1 条）再用 Embedding；Agent 据此回答，需要对比两个时间段时可以再检索一次。回答只陈述记录里写了什么，不替用户宣布进步。

## 目标用户

**核心用户**：持续上成人芭蕾课、希望把老师反馈和个人感受记下来的业余–进阶级学习者。

**当前验证阶段**：作品集 + 身边非正式试用。正式 **3–6 人结构化访谈尚未做**。家长端、老师端仍是假设画像，不是本版交付对象。

**用户痛点（仍成立）**

1. 课后只想随口说，不想打长笔记  
2. 口述零散，没有「优点 / 待改进 / 下次注意」  
3. 内容会忘，缺少可回看的档案  
4. （2.0 补上）记了很多次仍看不见「哪条问题反复出现」、上课前没有一张短卡

## 一句话定位

课后 1–3 段语音口述 → Whisper 转写 → Claude 结构化草稿 → 人确认后存档；跨课次用规则追踪反复问题、给课前短提醒；需要时用 RAG 和 Agent 查自己的档案。**AI 整理原话或并列引用已保存内容，不诊断动作，不替用户宣布进步。**

## In-Scope（当前产品真实范围）

1. 录 1–3 段语音，每段最多 60 秒；不支持语音时可手打  
2. 服务端 Whisper ASR（带芭蕾术语提示）；浏览器不支持时降级手打  
3. AI 抽取：做得好 / 待改进 / 下次注意 + 置信度 + note；tool-use 强制 schema  
4. Review / Edit / Retry / 确认保存；未确认不入库  
5. 历史档案：查看、删除、关键词搜索（中英法术语对照可搜）  
6. Progress：反复问题（文本匹配 + 用户改状态）、证据回链课次、课前卡（最多 3 条，**默认 0 次 LLM**）、最近 7 天 / 最近 5 次规则汇总。多 Agent 课前卡是 Experiment，双开关默认关，不对用户开，不计入已做范围。  
7. **问问你的档案**：追踪页提问。RAG 先关键词检索已确认课记；命中 0 或 1 条时再跑 Embedding。Agent 用 `ASK_PROMPT` 2.1 作答，可再按关键词/语义和时间范围检索一次。日期落在该用户自己的课记区间内。没有相关记录就如实说没有。  
8. 轻量账号：邮箱注册、JWT、隐私同意、找回密码；「我的」可导出全部数据或注销删账号（需密码确认）；记录按用户隔离  
9. 配额（转写、抽取、问问档案共用日限额）、Turso 持久化、内部 `/stats.html`、离线 Eval（约 35 条测抽取 Prompt；问问档案另有关键词/换说法对照集）  
10. **界面（2026-09-09）**：底栏四项（首页 / 记录 / 档案 / 追踪），「我的」从头像进；确认页默认只露三段笔记 + 保存，课名 / 时长 / 心情 / 小提示 / 转写在「还可以记下」；生成与保存吸底；首页日历默认一周、可展开整月；今天已写过则主按钮为「再记一笔」；可选心情为用户自报，AI 不推断

## Out-of-Scope（明确不做）

1. 视频动作识别、AI 打分、伤病/医疗诊断  
2. 社交、社区、分享  
3. 实时语音对话  
4. Fine-tuning、用模型写周报/月报、芭蕾百科问答、教练式对话  
5. 老师端、家长端、课程交易、会员分级  
6. 老师寄语对照、反复问题图表、课后主动 Push（方案另存，未做）  
7. 勾选式「未完成清单」、聚合场景专用 LLM Prompt  
8. 「心情色打卡」体系（连续打卡色、情绪评分）；现网仅有可选自报心情，与此不同

## 成功衡量（三层，不编目标数字）

**北极星（产品层）**  
同一 `sessionId` 的语音漏斗走到确认保存的比例：开始录音 → 录完 → ASR 成功 → AI 成功 → 打开 Review → 确认保存。  
禁止用「开过录音的独立账号 ÷ 保存过的独立账号」。

**Layer 1 AI 质量（离线 Eval）**  
Field Coverage、Classification、Hallucination-free / Unsupported Content、Terminology、Schema Validity。命令：`cd server && npm run eval`。

**Layer 2 系统**  
ASR/AI HTTP 成功率、P95 延迟、token、估算费用、失败原因、Retry。看板：`/stats.html`。原始埋点：同页底部按事件名查询（无转写/邮箱）。

**Layer 3 产品**  
Activation、Completion（session）、Edit Rate（≠ AI 错误率）、Regenerate、History Revisit、D7（样本极小时不当结论）。

次要指标 1.0 里把 Edit Rate 当成「AI 错了多少」——**2.0 纠正**：改口吻也算编辑。

## 核心风险与现网对策

| 风险 | 2.0 对策 |
| --- | --- |
| ASR 术语错 | Whisper + 术语 prompt；模型侧词汇表只用于「听懂」，对不上就降置信度；用户纠错过的术语写入后续 prompt |
| 口述太少 | 不补全；note「用户描述信息有限」；空字段合法 |
| 幻觉（编问题/建议） | Prompt 护栏 + tool schema + 人审；黄金集含 hallucination / injection / safety |
| 跨记录「你进步了」幻觉 | 反复问题 / 课前卡 / 窗口汇总 **默认不用 LLM**；问问档案只并列引用，Prompt 禁止进步/退步措辞 |
| 超时/失败 | 保留转写；Retry / 手打；日配额约 15 次；超时约 25s（AI）/ 30s（ASR） |
| 成本 | 生产模型 `claude-sonnet-5`（同质量、更便宜更快）；日限额 |
| 数据丢失 | 训练记录在 Turso，redeploy 不清空；本机每周 JSON dump 到私人目录 |
