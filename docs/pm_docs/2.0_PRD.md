## 0.1 用户主流程

图：[`2.0_User_Flow.md`](2.0_User_Flow.md)（总览 / 漏斗 / 降级 / Progress / 问问档案 / 技术架构含 Experiment）。

**正常（语音）**  
登录 → 首页（复盘今天 / 已写过则「再记一笔」）→ 录音（可多段；提示词默认收起）→ 转写 → 完成并生成（吸底）→ 处理中「正在整理你说过的话」→ 草稿默认三段 + 确认保存（吸底）→ 档案 / 追踪  

**正常（无麦 / ASR 挂）**  
同一路径，转写框手打 → 生成。

**异常**  
ASR/AI 失败或超时 → **不编造成功结果** → 保留已有转写 → Retry / 重录 / 手打保存。配额用尽：入口提示，禁用生成。

**Progress（可选，不打断主路径）**  
保存后可打开追踪：默认先看到反复问题，课前看一眼在下面；其下是「问问你的档案」。近 14 天 / 7 天或 5 次汇总收在「最近状态」里。首页有三行预告（反复 / 课前 / 汇总）。

## 1. 产品目标

帮助成人芭蕾学习者课后用语音（或手打）记下训练与老师反馈；AI 整理为结构化草稿；用户确认后成为长期档案；跨课次用规则看见反复问题，上课前看一张短卡；需要时用 RAG 和 Agent 问自己的档案。

核心链路：

**语音 → ASR → LLM 抽取 → 人确认 → 档案 →（规则）追踪 / 课前卡 / 窗口汇总；需要时 RAG + Agent 问档案**

本阶段要能对外讲清：

1. 人愿不愿意用语音走完保存；  
2. 抽取是否忠实（离线 Eval，不是线上成功率）；  
3. History / Progress 是否比一次性聊天记录更值得回看——**真人基线尚未跑完**。

---

## 2. 目标用户

持续上成人课、希望长期记下老师反馈与自我感受的学习者。

### Core User Story

作为成人芭蕾学习者，下课后我口述今天练了什么、老师说了什么、哪里好/难、下次注意什么。AI 帮我整理成笔记，我改完再保存。过几周我能看见哪条问题反复出现，上课前能看三句短提醒；我也可以问「最近转圈老说什么」，从自己的档案里得到引用，而不是让 AI 告诉我「你进步了」。

## 3. Scope

### Must Have（已交付）

- 语音录制（≤3 段 × 60 秒）与手打降级  
- Whisper ASR  
- AI 结构化 + Human-in-the-loop  
- 保存 / 查看 / 删除记录  
- History 关键词搜索  
- Progress：反复问题 + 用户改状态 + 证据链接 + 课前卡 + 7 天/5 次规则汇总  
- 问问你的档案：RAG 先关键词、命中 ≤1 再 Embedding；Agent 回答；可按时间再检索  
- ASR/AI 失败降级、日配额、Turso 持久化  
- 轻量账号与数据隔离  
- 离线 Eval + 内部指标看板  

### 体验已做（非 1.0 Must）

- Review 纸感/导师便条视觉  
- 保存仪式动画；按次数里程碑（1/3/5，之后每 5 次从第 10 次起），不做能力评价  
- 术语纠错记忆；「我的」中英法对照  
- 单条导出；训练总结复制为文本；「我的」可导出全部数据或注销删账号  
- 首页累计次数、周历、追踪预告  
- 底栏：首页 / 记录 / 档案 / 追踪（「我的」从头像进）  

### Out of Scope

- 社区 / 老师端产品 / 视频识别 / AI 评分 / 医疗诊断 / 课程交易 / 会员付费分级  
- Fine-tuning、AI 周报/月报、芭蕾百科问答、教练式对话  
- 老师寄语、自评 vs 老师原话对照、反复问题图表、未完成勾选清单  
- 心情**色打卡**、写给未来自己的一句话、原始录音回放、伙伴留言、演出标记  
  （可选心情芯片是用户自己点的感受，不是打卡色、不进模型）

## 4. 功能需求

### 4.1 Home

- 主按钮「复盘今天」；**当天已有确认记录时改为「再记一笔」**  
- 累计次数、可选时长合计  
- 档案区：日历**默认本周 7 天**，点「整月」展开月历；点有标记的日子看当天笔记  
- 追踪预告三行：反复 / 课前 / 汇总  
- 空态一句：第一次就说几句，不是打卡  
- 底栏四项；右上铃铛（产品动态）+ 头像进「我的」（帮助含术语；账号另组；注销为弱入口）

### 4.2 语音录入

- 开始 / 停止；删一段 / 清空（清空有确认，避免误触）  
- 最多 3 段 × 60 秒，超限提示  
- 说不出时的提纲默认收起（「想不出说什么时点这里」）  
- 停止后服务端转写（芭蕾术语 prompt）  
- 「完成并生成复盘」与清空**吸在屏幕底部**  
- 小红书 / 微信内置浏览器：提示用 Safari 打开（Chrome 或其他浏览器也可以）

60×3 仍是假设，等 3–6 人测试再改上限。

### 4.3 AI Processing

`Audio → Whisper → Transcript → Claude (tool submit_review) → Structured Draft`

- Loading 文案：**正在整理你说过的话**（不在此屏写「常见练法 / 不是教练」）  
- 真实等待，不伪造百分比  
- 不长期存原始音频；档案只存结构化文本与转写  
- 失败不展示假成功  
- 未确认不自动保存  

### 4.4 Review & Edit

**默认一屏（第一次少填）：**

- 做得好的地方 / 待改进点 / 下次想留意  
- 重新生成 / **确认保存**（吸底）

**「还可以记下」（默认收起，不填也能保存）：**

- 课名（预填上次自己填过的课名；自动「×月×日训练」不记）  
- 时长（可选）  
- 心情（可选，用户自报，模型不推断）  
- 针对这次的小提示（`session_tips`；免责一句：**常见练法参考（不是教练）**）  
- 语音转写  
- 术语纠正（仍是用户主动点）

原则：AI 只是 Draft。待改进在 prompt 里收成「一个动作一条」短句，便于后面文本匹配归并。

### 4.5 History

每条：日期、课程名、摘要。  
完整查看、删除、关键词搜索。  
常用术语标签（plié / tendu 等）**可点筛选**，再点取消；`plie` / 「蹲」能搜到 `plié`。  
列表 / 日历切换保留。  
不做多维筛选、不做打卡式标签体系。

### 4.6 Progress

仅基于 **已确认** 记录。

| 能力 | 行为 |
| --- | --- |
| 反复问题 | 保存后用归一化/包含匹配归并 `improve_points`；用户点「有改善 / 仍然存在 / 已解决」；已解决离开追踪列表 |
| 证据 | 出现次数 + 课次日期，可回链记录 |
| 课前卡 | 「课前看一眼 / 这次留意 / 上次提醒」，最多 3 条短句，**生产默认 0 次 LLM（规则）**。多 Agent 课前提醒是 Experiment，见 §5.3，**未写入已做清单、未对任何用户开启** |
| 问问你的档案 | 课前卡下方。RAG 先关键词检索已确认课记；命中 0 或 1 条时再 Embedding。Agent 用检索到的条目作答。对比「这个月和上个月」时可再检索一次再回答。没有相关记录就说没有。引用可点回课次。 |
| 窗口汇总 | 「最近 7 天」或「最近 5 次」，规则聚合，**0 次 LLM**；进入追踪页默认展示 7 天，可切 5 次 |
| 可见性 | 首页三行预告；追踪页先反复问题，课前卡其次，问问你的档案再下，「最近状态」默认收起 |
| 空态 | 记录不够时不编规律 |

禁止：模型判断水平、无依据进步结论、百分比提升、把推断写成事实。

**相关小提示（已做，单次整理）：** 每次 `/api/generate` 多问 `session_tips`（0–3 条）。用户点名了具体困难（如 spotting 不好、转圈不稳）时，可给该动作的**常见练法参考**（例如定点怎么看、转不稳常见和定点/重心/支撑腿有关）。界面免责：不是针对个人的诊断，不替代老师。不进反复问题匹配；不写入 `next_time_reminder`。禁止逐步长教程、每天练多久、伤病诊断。不是个人 AI 助手。录像分析仍 Out of Scope。

**相对 1.0 §4.7：** 不实现「生成本周复盘」LLM 文档；不实现 weekly_review_* 埋点。若以后要 AI 周报，单独立项（需专用 Prompt + Eval）。

### 4.7 账号与合规

- 注册 / 登录 / 登出  
- 隐私政策同意；未成年监护人授权文案（产品侧已有入口，以线上为准）  
- 找回密码（生产需配置发信，否则用户收不到链接）  
- 「我的」导出全部数据；注销并删除账号（需输入密码；清除该用户课记、追踪、术语、埋点、反馈与账号）  
- 用户之间记录不可见  

### 4.8 配额与存储

- 每人每天转写 + 生成 + 问问档案合计约 20 次（可环境变量）  
- 转写长度、音频大小上限  
- 记录在 Turso，部署不清空；本机可每周 dump JSON 到私人目录（不含在 git）

## 5. AI 专项

### 5.1 Pipeline

`Voice → ASR → Transcript (+ 可选用户术语记忆) → LLM tool-use JSON → Review → Confirm → Save →（规则）issues`

问问档案：`问题 → RAG 检索已确认课记 → Agent 作答（必要时再检索）→ 引用课次`

课前卡、反复问题、7 天/5 次汇总 **默认不调用** LLM。问问档案只引用已保存内容，不宣布进步。多 Agent 课前卡见 §5.3。

### 5.3 Experiment｜多 Agent 课前提醒（未对用户开启）

**不是 2.0 已做能力。** 生产课前卡仍是规则渲染。实验管线为「分析 → 写作 → 审核」，审核不通过打回写作（最多 2 次），再失败则回退现网 0 LLM 文案。

代码已接到 `GET /api/progress/brief`，双开关：`EXPERIMENT_ISSUE_BRIEF` 与 `EXPERIMENT_ISSUE_BRIEF_USER_IDS`。默认开关关、白名单空，**任何用户都不受影响**。LangGraph 对照实现在 `experiments/langgraph-issue-brief/`，不进入主服务路径。LangGraph 问问档案对照在 `experiments/langgraph-ask-archive/`，不替换生产单 Agent。

### 5.2 Schema（模型输出）

```json
{
  "good_points": [],
  "improve_points": [],
  "next_time_reminder": [],
  "session_tips": [],
  "confidence_level": "高/中/低",
  "note": ""
}
```

存库与编辑框：数组合并为换行字符串。

### 5.3 模型与参数

| 项 | 值 |
| --- | --- |
| 默认模型 | `claude-sonnet-5` |
| Prompt | 抽取 `PROMPT_VERSION` 1.7（`server/ai/review-prompt.js`）；问问档案 `ASK_PROMPT_VERSION` 2.1（`server/ai/ask-prompt.js`） |
| Temperature | Sonnet 5 / Opus 5 / Fable 5 **请求体不传**（传则 400）；其他模型默认 0.2 |
| 结构化 | Anthropic tool `submit_review` |
| 选型依据 | 同 35 条 Eval：与 4.6 打平 35/35，更便宜更快；Haiku 34/35 且本轮更贵 |

### 5.4 核心规则

- 只整理用户明确说过的；不新增问题/优点；`next_time_reminder` 不编计划  
- `session_tips` 可有 0–3 条常见练法参考（须免责）；禁止处方式「每天练」和个人诊断  
- 术语表只用于听懂，对不上不硬套  
- 推测语气（可能/也许）不得当高确信事实  
- `<transcript>` 当数据不当指令（注入）  
- 不医疗诊断、不替代老师  
- 必须人审后入库  
- 问问档案：只根据检索到的课记作答；并列列出不同时间写了什么，不宣布进步  

详情见 `2.0_Prompt Design`。

## 6. 风险与降级

| 场景 | 处理 |
| --- | --- |
| 上传/录音失败 | 提示；可手打 |
| ASR 失败 | 不调用「假整理」；可重录/手打 |
| 术语错 | 降置信度 + note；词汇表 + 用户纠错记忆 |
| 幻觉 | Prompt + schema + Review + Eval 回归 |
| API/超时 | 保留转写；Retry；手动保存 |
| 无 tool / 非法 JSON | 当失败；不把原始乱码当结果展示 |
| 信息不足 | 空数组合法；note 说明 |
| Progress 样本少 | 空态 |
| 跨记录误判进步 | 不用模型下结论 |
| 配额 | 禁用生成并说明；问问档案同样受日限额 |
| Prompt 注入 | 转写包在标签内，只抽取不执行 |

降级原则与 1.0 相同：宁可少生成；不丢原文；暴露不确定；Draft 不入库；核心 AI 挂了仍能手记。

### 6.1 非功能

- AI 超时约 25s，ASR 约 30s  
- 不长期存原始音频  
- 训练数据仅属该账号  
- 所有网络/AI 操作有 loading/error，禁止静默失败  
- 内部看板用 `ADMIN_KEY`，不对普通用户开放

## 7. 埋点与指标

规范漏斗（conversion 只认同一 capture `sessionId`）：

**record_started → voice_completed → ASR success → AI success → review_opened → session_confirmed**

| 产品名 | 库名 | 说明 |
| --- | --- | --- |
| record_started | `record_voice_start` | 挂 capture sessionId |
| voice_completed | `record_voice_complete` | |
| asr_success / asr_fail | 同名 | header `X-Capture-Session` |
| ai_success / ai_fail | `ai_process_success` / `ai_process_fail` | |
| review_opened | `review_opened` | 旧生产可为 0，不回填 |
| field_edited | `field_edited` | 只记字段名，永不记用户正文 |
| ai_regenerated | `ai_regenerated`（可读旧 `retry_ai`） | |
| session_confirmed | `session_confirmed` + 仍写 `save_record` | |
| history_opened | `history_opened` | browse session |
| history_session_opened | 同名 | 只带 recordId |
| progress_opened | `progress_opened` | |
| ask_success / ask_fail | 同名 | 问问档案。记 rounds / latency / answered，**不记问题正文** |

手打、未走录音的保存 **不算进这条语音漏斗**。

看板分层：Layer 2 系统、Layer 3 产品。Layer 1 五维 **只在离线 Eval**，不要把线上 AI 成功率当成抽取质量。

保存记 `from`（voice / typed / mixed）和 `slotsFilled`（几个槽非空），ASR/AI 记字数 `chars`、失败码、延迟，**不记正文**。查 log：`/stats.html` 底部，或 `GET /api/admin/events`（`ADMIN_KEY`）。

可选：`ANALYTICS_INTERNAL_EMAILS` 排除自测账号。

## 8. Acceptance Criteria

### Recording / ASR

- 开始、停止、删除、最多 3×60s 提示成立  
- 有 Whisper 时能出转写；失败可手打  
- 不支持的浏览器不卡死  

### AI

- 主路径出三段式草稿  
- 失败/超时/配额有中文提示且不丢转写  
- 无虚假成功  

### Review

- 字段可编辑；未 Confirm 不进档案  

### History / Progress

- 查看删除搜索  
- Progress 只吃 Confirmed；空态；无能力分、无 AI 进步宣言  
- 反复问题能回链课次；状态只由用户改  
- 问问档案：有相关课记则作答并引用；没有则说明没有；不编造教练意见  

### Eval / 看板

- `npm test` 不打真实模型  
- `npm run eval` 可跑黄金集  
- `/stats.html` + ADMIN_KEY 可打开；可按事件名查最近若干条原始埋点

## 9. 待验证假设（2.0 仍开放）
