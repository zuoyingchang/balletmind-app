## 1. 问题与场景

成人芭蕾学习者课后普遍面临三个问题：**课后反馈容易丢失、训练记录分散、长期进步难追踪**。市面工具多是通用录音/笔记类产品，没有针对垂直学习场景的结构化沉淀和长期追踪能力。

核心链路：**语音记录 → AI 结构化 → 用户确认 → 保存 → 成长追踪**。

## 2. 为什么用 AI，为什么不用 Agent / RAG / 微调

这是面试最常被追问的一步，答案是明确的技术/产品权衡，不是「没时间做」：

- **不微调**：没有大规模标注的「正确复盘」样本，任务是忠实抽取而非生成，Prompt + Schema 已经够用。
- **不做 RAG**：当前场景是单次 session 的结构化抽取，没有外部知识检索需求；把用户历史记录交给模型去下「你进步了」的结论，幻觉风险远高于规则匹配。
- **不做多步 Agent**：课后一次性整理，不是连续工具调用的工作流。引入 Agent 只会增加延迟、成本和失败面。
- **跨记录的"理解"环节刻意不用大模型**：反复问题追踪、课前预习卡、周期汇总全部走规则聚合（文本相似匹配 + 用户自己确认状态），不让模型对「用户是否进步」下无法验证的结论。这是产品对 AI 能力边界和用户信任的主动判断，也是本项目最能体现 AI PM 判断力的一点。

## 4. AI 质量保障：评测驱动迭代

建立离线评测集（35 条，覆盖忠实提取、拒绝幻觉、术语识别、Prompt 注入防御、中英法术语混杂、医疗类内容规避、空白输入等场景）。一条真实 bad case 走完了完整的「发现→定位→修复→回归验证」闭环：

- **发现**：术语识别是高频失败模式，ASR 把法语/口语化芭蕾术语（如 grand battement）转写得面目全非。
- **定位**：归因到 Prompt 层面而非 ASR——模型面对陌生拼写时要么放弃识别，要么强行套用错误术语。
- **修复**：新增芭蕾术语表（覆盖位置、把杆、转、跳、造型、足尖词汇），并加入用户纠错记忆机制——用户手动纠正一次后，该纠正会写回后续 Prompt。
- **验证**：用评测集里对应的两个 case（「术语表识别」「真正无法辨认的术语不能硬编」）验证回归，确认修复没有引入新的过度自信问题。

Prompt 版本号（当前 v1.5）与 temperature 参数化基础设施已就位，支撑后续多模型/参数对比时「只改一个变量」。

## 5. 模型选型决策

同一套 35 条评测、同一 Prompt 版本，对比三个模型：

| 指标 | Sonnet 4.6 | **Sonnet 5**（选定） | Haiku 4.5 |
|---|---|---|---|
| Eval 质量（35条通过率） | 35/35 | **35/35** | 34/35 |
| 平均延迟 | 3403 ms | **2454 ms** | 1848 ms |
| 35条估算成本 | $0.1705 | **$0.1047** | $0.1482（cache未命中，实际更贵） |

**决策：生产切到 Sonnet 5**——质量打平，延迟降低约28%，成本降低约39%。Haiku 单价最低但本轮未吃到 cache，实际总成本反而更高，且漏掉一个「含糊表述不该硬造具体动作名」的 case，在"不编造用户没说过的内容"这条产品红线上不如两个 Sonnet 可靠。唯一代价是接口兼容性：Sonnet 5 请求体不能再传 `temperature`（会整批 400），已在代码里按模型名判断跳过该字段。完整对照见 `Eval_Model_Selection_Report.md`。

## 6. 可观测性

三层指标框架：
- **AI 质量层**：Field Coverage、Classification Accuracy、Unsupported Content Rate（幻觉）、Terminology Accuracy、Schema Validity——来自离线评测。
- **系统层**：P95 延迟、重试/超时次数、token 用量、估算成本——`/stats.html` 内部看板实时可查。
- **产品层**：`record_voice_start → asr_success → ai_process_success → review_opened → user_edit_ai_result → save_record → history_open → progress_open` 全链路埋点。

## 7. 现在的真实状态（不装作比实际更完美）

- 生产 AI 调用成功率 100%（HTTP+schema层面），核心通知链路稳定。
- Edit Rate 目前记录为 0%，但样本量小且埋点刚补全，**不能**当作"AI输出完美"的证据，需要更多真实使用后重新读数。
- 激活率、留存等产品指标目前主要来自内部自测和少量朋友/亲戚测试账号，**尚未开放给真实陌生用户**，样本不具备统计意义。
- 尚未完成 3-6 人结构化真实用户测试——这是目前portfolio里最大的空白，价值高于继续扩大评测集或加新功能。
- 习惯养成机制目前是"被动"的（打开App才看得到里程碑/连续训练提示），没有主动提醒用户回来记录的机制（无push/邮件提醒）。
