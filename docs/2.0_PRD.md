## 0.1 用户主流程

**正常（语音）**  
登录 → Home → 开始复盘 → 录音（可多段）→ 转写 → Generate → Review/Edit → Confirm & Save → 历史 / Progress

**正常（无麦 / ASR 挂）**  
同一路径，转写框手打 → Generate。

**异常**  
ASR/AI 失败或超时 → **不编造成功结果** → 保留已有转写 → Retry / 重录 / 手打保存。配额用尽：入口提示，禁用生成。

**Progress（可选，不打断主路径）**  
保存后可打开追踪页：反复问题列表、课前卡、7 天或 5 次汇总、回链单次记录。

## 1. 产品目标

帮助成人芭蕾学习者课后用语音（或手打）记下训练与老师反馈；AI 整理为结构化草稿；用户确认后成为长期档案；跨课次用规则看见反复问题，上课前看一张短卡。

核心链路：

**语音 → ASR → LLM 抽取 → 人确认 → 档案 →（规则）追踪 / 课前卡 / 窗口汇总**

本阶段要能对外讲清：

1. 人愿不愿意用语音走完保存；  
2. 抽取是否忠实（离线 Eval，不是线上成功率）；  
3. History / Progress 是否比一次性聊天记录更值得回看——**真人基线尚未跑完**。

---

## 2. 目标用户

持续上成人课、希望长期记下老师反馈与自我感受的学习者。

### Core User Story

作为成人芭蕾学习者，下课后我口述今天练了什么、老师说了什么、哪里好/难、下次注意什么。AI 帮我整理成笔记，我改完再保存。过几周我能看见哪条问题反复出现，上课前能看三句短提醒，而不是让 AI 告诉我「你进步了」。

---

## 3. Scope

### Must Have（已交付）

- 语音录制（≤3 段 × 60 秒）与手打降级  
- Whisper ASR  
- AI 结构化 + Human-in-the-loop  
- 保存 / 查看 / 删除记录  
- History 关键词搜索  
- Progress：反复问题 + 用户改状态 + 证据链接 + 课前卡 + 7 天/5 次规则汇总  
- ASR/AI 失败降级、日配额、Turso 持久化  
- 轻量账号与数据隔离  
- 离线 Eval + 内部指标看板  

### 体验已做（非 1.0 Must）

- Review 纸感/导师便条视觉  
- 保存仪式动画；按次数里程碑（1/3/5，之后每 5 次从第 10 次起），不做能力评价  
- 术语纠错记忆；「我的」中英法对照  
- 单条导出；训练总结复制为文本  
- 首页「一共记了几次」为累计保存数  

### Out of Scope

- 社区 / 老师端产品 / 视频识别 / AI 评分 / 医疗诊断 / 课程交易 / 会员付费分级  
- Agent、Fine-tuning、RAG、Ask My Training、AI 周报/月报  
- 老师寄语、自评 vs 老师原话对照、反复问题图表、未完成勾选清单  
- 心情色、未来自己一句话、原始录音回放、伙伴留言、演出标记

## 4. 功能需求

### 4.1 Home

- 「开始训练复盘」  
- 累计次数、最近记录  
- 有数据时的轻提示（非 AI 能力评分）  
- 空态：完成第一次记录后这里会形成档案  

### 4.2 语音录入

- 开始 / 停止；删一段 / 清空  
- 最多 3 段 × 60 秒，超限提示  
- 引导：今天练了什么、老师反馈、哪里好、哪里难、下次注意什么  
- 停止后服务端转写（芭蕾术语 prompt）  
- Generate 进入整理  

60×3 仍是假设，等 3–6 人测试再改上限。

### 4.3 AI Processing

`Audio → Whisper → Transcript → Claude (tool submit_review) → Structured Draft`

- Loading：正在转写 / 正在整理（真实等待，不伪造百分比）  
- 不长期存原始音频；档案只存结构化文本与转写  
- 失败不展示假成功  
- 未确认不自动保存  

### 4.4 Review & Edit

展示并可改：

- 做得好的地方  
- 待改进点  
- 下次注意  
- Confidence、Note（展示不确定性；用户以编辑正文为准）  

操作：改 / 删 / 补、Retry、重录、Confirm & Save。

原则：AI 只是 Draft。

待改进在 prompt 里收成「一个动作一条」短句，便于后面文本匹配归并。

### 4.5 History

每条：日期、课程名、摘要。  
支持完整查看、删除、关键词搜索。  
不做标签体系、不做多维筛选。

### 4.6 Progress（已做，规则版）

仅基于 **已确认** 记录。

| 能力 | 行为 |
| --- | --- |
| 反复问题 | 保存后用归一化/包含匹配归并 `improve_points`；用户点「有改善 / 仍然存在 / 已解决」；已解决离开追踪列表 |
| 证据 | 出现次数 + 课次日期，可回链记录 |
| 课前卡 | 「课前看一眼 / 这次留意 / 上次提醒」，最多 3 条短句，**0 次 LLM** |
| 窗口汇总 | 「最近 7 天」或「最近 5 次」，规则聚合，**0 次 LLM** |
| 空态 | 记录不够时不编规律 |

禁止：模型判断水平、无依据进步结论、百分比提升、把推断写成事实。

**相对 1.0 §4.7：** 不实现「生成本周复盘」LLM 文档；不实现 weekly_review_* 埋点。若以后要 AI 周报，单独立项（需专用 Prompt + Eval）。

### 4.7 账号与合规

- 注册 / 登录 / 登出  
- 隐私政策同意；未成年监护人授权文案（产品侧已有入口，以线上为准）  
- 找回密码（生产需配置发信，否则用户收不到链接）  
- 用户之间记录不可见  

### 4.8 配额与存储

- 每人每天转写 + 生成合计约 30 次（可环境变量）  
- 转写长度、音频大小上限  
- 记录在 Turso，部署不清空

## 5. AI 专项

### 5.1 Pipeline

`Voice → ASR → Transcript (+ 可选用户术语记忆) → LLM tool-use JSON → Review → Confirm → Save →（规则）issues`

跨记录路径 **不调用** LLM。

### 5.2 Schema（模型输出）

```json
{
  "good_points": [],
  "improve_points": [],
  "next_time_reminder": [],
  "confidence_level": "高/中/低",
  "note": ""
}
```

存库与编辑框：数组合并为换行字符串。

### 5.3 模型与参数

| 项 | 值 |
| --- | --- |
| 默认模型 | `claude-sonnet-5` |
| Prompt | `PROMPT_VERSION` 1.5（`server/ai/review-prompt.js`） |
| Temperature | Sonnet 5 / Opus 5 / Fable 5 **请求体不传**（传则 400）；其他模型默认 0.2 |
| 结构化 | Anthropic tool `submit_review` |
| 选型依据 | 同 35 条 Eval：与 4.6 打平 35/35，更便宜更快；Haiku 34/35 且本轮更贵 |

### 5.4 核心规则

- 只整理用户明确说过的；不新增问题/优点/建议  
- 术语表只用于听懂，对不上不硬套  
- 推测语气（可能/也许）不得当高确信事实  
- `<transcript>` 当数据不当指令（注入）  
- 不医疗诊断、不替代老师  
- 必须人审后入库  

详情见 `2.0_Prompt Design`。

## 6. 风险与降级

| 场景 | 处理 |
| --- | --- |
| 上传/录音失败 | 提示；可手打 |
| ASR 失败 | 不调用「假整理」；可重录/手打 |
| 术语错 | 降置信度 + note；词汇表 + 用户纠错记忆 |
| 幻觉 | Prompt + schema + Review + Eval 回归 |
| API/超时 | 保留转写；Retry；手动保存 |
| 无 tool / 非法 JSON | 当失败；不把原始乱码当结果展示 |
| 信息不足 | 空数组合法；note 说明 |
| Progress 样本少 | 空态 |
| 跨记录误判进步 | 不用模型下结论 |
| 配额 | 禁用生成并说明 |
| Prompt 注入 | 转写包在标签内，只抽取不执行 |

降级原则与 1.0 相同：宁可少生成；不丢原文；暴露不确定；Draft 不入库；核心 AI 挂了仍能手记。

### 6.1 非功能

- AI 超时约 25s，ASR 约 30s  
- 不长期存原始音频  
- 训练数据仅属该账号  
- 所有网络/AI 操作有 loading/error，禁止静默失败  
- 内部看板用 `ADMIN_KEY`，不对普通用户开放

## 7. 埋点与指标

规范漏斗（conversion 只认同一 capture `sessionId`）：

**record_started → voice_completed → ASR success → AI success → review_opened → session_confirmed**

| 产品名 | 库名 | 说明 |
| --- | --- | --- |
| record_started | `record_voice_start` | 挂 capture sessionId |
| voice_completed | `record_voice_complete` | |
| asr_success / asr_fail | 同名 | header `X-Capture-Session` |
| ai_success / ai_fail | `ai_process_success` / `ai_process_fail` | |
| review_opened | `review_opened` | 旧生产可为 0，不回填 |
| field_edited | `field_edited` | 只记字段名，永不记用户正文 |
| ai_regenerated | `ai_regenerated`（可读旧 `retry_ai`） | |
| session_confirmed | `session_confirmed` + 仍写 `save_record` | |
| history_opened | `history_opened` | browse session |
| history_session_opened | 同名 | 只带 recordId |
| progress_opened | `progress_opened` | |

手打、未走录音的保存 **不算进这条语音漏斗**。

看板分层：Layer 2 系统、Layer 3 产品。Layer 1 五维 **只在离线 Eval**，不要把线上 AI 成功率当成抽取质量。

可选：`ANALYTICS_INTERNAL_EMAILS` 排除自测账号。

## 8. Acceptance Criteria

### Recording / ASR

- 开始、停止、删除、最多 3×60s 提示成立  
- 有 Whisper 时能出转写；失败可手打  
- 不支持的浏览器不卡死  

### AI

- 主路径出三段式草稿  
- 失败/超时/配额有中文提示且不丢转写  
- 无虚假成功  

### Review

- 字段可编辑；未 Confirm 不进档案  

### History / Progress

- 查看删除搜索  
- Progress 只吃 Confirmed；空态；无能力分、无 AI 进步宣言  
- 反复问题能回链课次；状态只由用户改  

### Eval / 看板

- `npm test` 不打真实模型  
- `npm run eval` 可跑黄金集  
- `/stats.html` + ADMIN_KEY 可打开
