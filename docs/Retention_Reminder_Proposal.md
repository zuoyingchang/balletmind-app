# BalletMind｜主动提醒机制方案（解决"打卡完全被动"的问题）

> 更新：2026-09-08
> 背景：现有的里程碑/连续训练提示都是"打开App才看得到"，App从不主动找用户。这份方案给出一个**低成本、复用现有基础设施、可衡量**的做法，不引入过度设计。

---

## 现状（已有的，不用重做）

- `server/milestones.js`：连续周数 streak 计算逻辑已存在，只是只在保存时展示。
- `server/routes/auth.js`：已经在用 Resend 发密码重置邮件，`RESEND_API_KEY` / `EMAIL_FROM` / `APP_PUBLIC_URL` 三个环境变量已就位。
- `.github/workflows/`：已经有一个 GitHub Actions 定时任务（每10分钟 ping 一次防止 Render 休眠），证明这个"定时触发外部调用"的模式已经在用，不是新技能。

结论：加提醒不需要引入新的第三方服务或复杂基础设施，两块积木已经有了，缺的是把它们接起来。

---

## 方案：分阶段做，每阶段独立验证价值再往下走

### 阶段 0（今天就能做，前端改动，零后端成本）

首页现在的"训练小提示"轮播位置，改成：如果用户有过记录，展示"距离上次记录已经 N 天"；如果从没记录过，维持现有的鼓励文案。纯前端算，用已经拉取到的 `historyRows` 就能算出来，不需要新接口。

**这不是"主动提醒"**（用户不打开App还是看不到），但成本几乎为零，可以先上。

### 阶段 1（核心方案）：邮件提醒

**触发条件：**
- 用户至少保存过 1 条记录（已激活用户，跳过从没用过的账号，那批人邮件提醒解决不了"没上手"的问题）
- 最近 N 天（建议从 7 天开始，后续可调）没有新记录

**频率与退出：**
- 每个用户每周最多收到 1 封，避免变成骚扰
- 邮件必须带一键退订链接，写入 `users` 表一个新字段（如 `reminders_enabled`），退订后彻底不再发

**文案原则：**
延续这个产品"不评价用户表现"的一贯态度——不写"你已经落后了"这种施压语言，类似"好久没见你来记录了，花3分钟说说这周练了什么"。

**技术实现：**
1. 新增一个内部专用接口（`POST /api/internal/send-reminders`，用类似 `ADMIN_KEY` 的密钥保护，不对外暴露），逻辑：查询"已激活 且 最近7天无新记录 且 未在本周收到过提醒 且 未退订"的用户列表，逐个调用 Resend 发信，发送成功后记录到 `events` 表（新增一个 `reminder_sent` 事件类型，天然做到"本周发过就不重复发"的幂等）。
2. 把 `routes/auth.js` 里现成的 Resend 调用逻辑抽成 `server/lib/email.js` 的小 helper，两处复用。
3. 复用已有的 GitHub Actions 定时任务模式，新增一个 workflow，一天跑一次，调用上面这个接口。

**工作量估计：** 后端一个新路由 + 一个 helper + 一张事件类型，前端一个退订页面，一个新 GitHub Actions workflow。跟现有代码风格一致，不引入新依赖。

### 阶段 2（先别做，等阶段1验证有效再考虑）：更主动的通道

Web Push（浏览器推送）或做成 PWA 加桌面图标 + 系统通知，能在用户没打开邮箱的情况下也提醒到。但代价明显更高：需要 Service Worker、VAPID 密钥管理、用户主动授权浏览器通知权限，而且现在是朋友测试阶段，用户量还小，投入产出比不划算。

**触发升级到阶段2的条件：** 阶段1的邮件打开率和"提醒后48小时内回访率"有正向信号，且用户量增长到邮件触达率明显不够用的程度。

---

## 怎么判断这个方案有没有用（不是做完就算，要能衡量）

| 指标 | 怎么看 |
|---|---|
| 邮件打开率 | Resend 本身应该能拿到这个数据（或者邮件里加一个不可见追踪像素，如果Resend不直接提供） |
| 提醒后48小时回访率 | 收到提醒的用户里，多少比例在48小时内产生了新的 `save_record` 事件；对比同一批用户在没收到提醒时的自然回访率 |
| 退订率 | 如果退订率明显偏高，说明文案或频率有问题，需要调整，而不是加大力度 |
| 次周留存 | 长期看，有没有带动"第二周还会不会回来"这个更本质的问题 |

---

## 明确不做（避免过度设计）

- **不做每日强提醒**：容易变成骚扰，也和产品"不给用户压力、不评价表现"的调性冲突（这跟"早睡干预"类锁屏App的强提醒逻辑是两种产品哲学，BalletMind 应该选温和的那种）。
- **不做短信**：成本更高，朋友测试阶段没必要。
- **不做复杂的个性化提醒时间算法**（比如猜测用户上课时间）：先用固定的简单规则（N天未记录→发一次）跑通并验证，有真实数据支撑再迭代到更聪明的版本。
